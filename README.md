# 切り札は最後に — LAST TRUMP

5枚、5回、一瞬の逆転。iPhoneの縦画面を中心に作った、日本語のCPU対戦カードゲームです。**dots / OpenAI CodexによるAI制作**。MIT License、Copyright (c) 2026 monnouchi。

## 遊び方

1. 双方が同じ1〜5を持ち、手札をタップして選びます。確定前は変更できます。
2. 「伏せて勝負」で同時公開。大きい数字が勝ちますが、**1だけは5に勝ちます**。
3. 使った札は戻りません。CPUの残り札と下部の公開履歴を見て、温存・捨て札を判断します。
4. 第1〜3戦は1点、第4〜5戦は2点。同じ札なら双方0点で、得点の持ち越しはありません。
5. 必ず5戦で終了し、合計得点で決着。同点なら引き分けです。延長・早期終了・課金要素はありません。

後半2戦の重みだけを加え、強い札から順に出す単調さを避けています。考える時間によりますが、1試合の目安は1〜3分。強制タイマーはありません。通常の演出待ちは1戦約1.5秒、最終戦のみ約2.05秒です。

音は初期OFF。ONにすると、選択・溜め・激突・逆転・決着をWeb Audioで鳴らします。操作後にAudioContextを開始し、音設定だけをlocalStorageに保存します。外部音源・フォント・画像・解析通信・サーバー処理は使いません。`prefers-reduced-motion`では移動、回転、粒子、閃光を止め、短い表示切替にします。

## ローカル実行

Node.js 20以上。実行時・ビルド時のnpm依存パッケージはありません。`npm install`も不要です。

```sh
npm run dev        # http://localhost:4173
npm test           # ルールとCPU公平性
npm run balance    # 固定seed、6戦略 × 20,000試合
npm run build      # dist/ に静的ファイルを生成
npm run preview    # dist/ を http://localhost:4173 で確認
```

開発サーバーとプレビューは同じポートです。同時に動かす場合は `PORT=4174 npm run preview` のように変更してください。サーバーはLAN実機検証用に `0.0.0.0` で待受します。開発サーバーを本番公開せず、配信には `dist/` を使ってください。

モバイルUI検証はPythonのPlaywrightとChromiumを使います（ゲーム本体の依存ではありません）。プレビュー起動後に実行します。

```sh
python tests/mobile.py
# 必要に応じて CHROMIUM_PATH=/path/to/chromium TEST_URL=http://localhost:4173 を指定
# インストール済みWebKitがあれば BROWSER=webkit python tests/mobile.py
```

スクリーンショットと機械可読結果は `artifacts/` に生成され、Git管理には含めません。

## CPUの公平性・戦略

`src/game.js` の `prepareRound()` が、**プレイヤー入力を有効にする前**にCPUの札を確定します。受け取るのは双方の公開情報から分かる残り手札と、公開済みの履歴だけです。現在選択中の札は引数になく、確定したCPU札はクロージャに保持します。公開は一度だけ可能です。ゲームはオフラインの一人用で、開発者ツールによる自己改変への対策は目的としていません。

残りの相手札を一様分布と仮定し、後半の点数も含めて将来の期待得点差を探索します。温度0.7のsoftmaxに15%の一様分布を混ぜるため、固定順にはなりません。ユーザーの選択癖の学習や、見えていない札の参照はありません。勝率最大化の完全な均衡戦略ではなく、短いカジュアル対戦用です。

`scripts/balance.mjs` の最善応答はCPUの**分布**を知るプレイヤーを評価します。実際に抽選された未公開札は参照せず、最終的な勝ち・負け・引き分けを評価しています。

## 検証・レビュー（2026-10-02）

- `npm test`: 7テスト成功。25通りの対面、全14,400通りの5戦の並び、対称性、得点、引き分け、消費済み札、入力不変性、二重公開拒否を確認。
- 同じ乱数でプレイヤーの選択を全5通りに変えてもCPU札が不変。CPU乱数は事前確定時の1回のみ。全251通りの等サイズの残り手札ペアで合法性・確率の正規化を確認。
- 固定seed `20261002`、各20,000試合の結果は以下。W/D/Lはプレイヤー側です。統計は人間の難易度評価ではありません。

| プレイヤー戦略     |   勝ち | 引き分け |   負け |
| ------------------ | -----: | -------: | -----: |
| 無作為             | 36.86% |   15.47% | 47.66% |
| 小さい札から       | 45.90% |   27.39% | 26.71% |
| 大きい札から       | 25.90% |    6.22% | 67.88% |
| 2 → 3 → 4 → 1 → 5  | 42.20% |   23.50% | 34.31% |
| CPUと同じ戦略      | 40.70% |   17.79% | 41.52% |
| 分布を知る最善応答 | 59.17% |   14.44% | 26.39% |

最善応答の厳密な期待値（勝率−敗率）は0.32344。CPUは無敵ではなく攻略余地があります。同戦略同士はほぼ互角。無作為戦略では、第3戦時点のリードが最後に逆転した試合は32.00%でした。

UIはChromiumのタッチ端末エミュレーションで、320×568、375×548、375×667、390×664、390×844、430×932を検証しました。主要操作・公開履歴の画面内配置、札の変更、ルール画面、音設定保存、勝ち・負け・引き分けまでの通しプレイ、12連打時の入力ロック、リスタート、reduced-motion、キーボード操作、localStorageが使えない場合を確認。計12シナリオで実行中のJavaScript例外は0件。390×844・390×664ではノッチ47px／ホームインジケーター34pxを模擬し、主要操作が安全領域内に収まることも確認しました。レイアウト確認で見つかった小型画面の履歴はみ出しは修正済みです。

**未確認**: iPhone Safari実機での描画・音の聞こえ方・端末固有のオーディオ復帰・VoiceOver。WebKitのダウンロードは環境の通信制限（403 Domain forbidden）により失敗したため、Safari/WebKit試験済みとはしていません。実機の音量・触感や人間のプレイ感は、エミュレーションの結果とは区別してください。

## 構成

- `index.html`: 日本語の対戦画面・ルールダイアログ
- `src/game.js`: 純粋な勝敗処理・CPU探索・事前確定
- `src/app.js`: 入力状態、カード演出、粒子、Web Audio
- `src/style.css`: レスポンシブ配置、カード装飾、reduced-motion
- `scripts/`: 依存不要のビルド・プレビュー、バランス測定
- `tests/`: ルール/公平性単体テストとモバイル操作回帰テスト
