# Duel Five

5枚、5回、一瞬の逆転。iPhoneの縦画面を中心に作った、日本語のCPU対戦カードゲームです。**dots / OpenAI CodexによるAI制作**。MIT License、Copyright (c) 2026 monnouchi。

## ブラウザで遊ぶ

**[Duel Fiveを遊ぶ](https://monnouchi.github.io/duel-five/)** — インストール不要の一人用CPU対戦です。

ゲーム画面・遊び方・終幕・ブラウザのタイトル・共有プレビューの名称は「Duel Five」で統一しています。

## 遊び方

1. 最初に短いルール説明が開きます。「遊ぶ」で開始。双方が同じ1〜5を持ち、手札をタップして選びます。
2. 選択した同じ札をもう一度タップすると同時公開。別の札で選び直せます。「この札で勝負」ボタンでも確定できます。最初のタップ直後450ms以内の同札連打は確定しません。大きい数字が勝ちますが、**1だけは5に勝ちます**。
3. 使った札は戻りません。CPUの残り札と下部の公開履歴を見て、温存・捨て札を判断します。
4. 第1〜3ラウンドは1点、第4〜5ラウンドは2点。同じ札なら双方0点で、得点の持ち越しはありません。
5. 必ず5ラウンドで終了し、合計得点で決着。同点なら引き分けです。延長・早期終了・課金要素はありません。

後半2ラウンドの重みだけを加え、強い札から順に出す単調さを避けています。考える時間によりますが、1試合の目安は1〜3分。強制タイマーはありません。終了後は合計点・足し算の内訳・各ラウンドの得点を表示します。勝敗数は参考情報として小さく表示します。通常の演出待ちは1ラウンド約1.5秒、最終ラウンドは約2.05秒。1が5を倒す逆転は約0.3秒の溜めを追加します。第4ラウンドの結果を確認して「残り1枚で最終決着を見る」を押すと、最後の札は自動公開されます。

先鋒・次鋒・中堅・副将・大将の5人勝ち抜き。各相手との5ラウンドに勝つと次へ進み、負け・引き分けは同じ相手に再挑戦します。通算の完了試合数・勝敗・引き分けと進行を端末内に保存します。途中で閉じた試合は数えず、同じ相手との試合の最初から再開。大将に勝つと専用の終幕画面と短いファンファーレで五人制覇を祝います。獲得した王冠・制覇回数・通算成績を記録し、再読込後も終幕を表示します。再読込時には音や登場演出を繰り返しません。「もう一度遊ぶ（任意）」は控えめな操作として残し、通算・王冠を保って再開できます。

5ラウンド全勝・全敗・全引き分けには専用の決着表示があります。全敗時も再挑戦を促す表現にしています。固定したプレイヤーの出し順に対し、それぞれに対応する相手の出し順は120通り中1通り。これは相手の全順列が等確率の場合に限る確率で、戦略CPUの実際の発生率ではありません。

音は初期OFF。ONにすると、選択・溜め・激突・逆転・決着をWeb Audioで鳴らします。操作後にAudioContextを開始し、音設定と勝ち抜き進行・通算成績をlocalStorageに保存します。刺客の斬撃、双刃の二連斬、騎士の衝撃、女王の光、王冠の放射を勝った札ごとに変え、CPUの勝利は別の色で示します。音はプレイヤー視点の勝利（高い上昇音）・敗北（低い下降音）を先に示し、その後に札の音色・リズムを添えます。CPUの逆転にも成功音を使いません。相打ちは1〜2msの速い立ち上がりと非整数倍の倍音を使う、約0.15秒の金属衝突音です。合成ピークの設定値は従来より低く、音量増加には頼っていません。ミュート時には予約済みの音も停止します。第5ラウンドの音が終わってから決着音を鳴らし、制覇音は通常勝利・全勝の音に優先して一度だけ鳴ります。外部音源・フォント・画像・解析通信・サーバー処理は使いません。`prefers-reduced-motion`では移動、回転、粒子、閃光を止め、短い表示切替にします。

## ローカル実行

Node.js 20以上。実行時・ビルド時のnpm依存パッケージはありません。`npm install`も不要です。

```sh
npm run dev        # http://localhost:4173
npm test           # ルールとCPU公平性
npm run balance    # 副将を対象に6戦略を比較
npm run balance:ladder # 5人 × 5戦略 × 20,000試合
node scripts/ascending-exact.mjs # 昇順固定に対するCPU全経路の厳密集計
npm run build      # dist/ に静的ファイルを生成
npm run preview    # dist/ を http://localhost:4173 で確認
```

開発サーバーとプレビューは同じポートです。同時に動かす場合は `PORT=4174 npm run preview` のように変更してください。サーバーはLAN実機検証用に `0.0.0.0` で待受します。開発サーバーを本番公開せず、配信には `dist/` を使ってください。

モバイルUI検証はPythonのPlaywrightとChromiumを使います（ゲーム本体の依存ではありません）。プレビュー起動後に実行します。

```sh
python tests/mobile.py
python tests/release.py # 旧保存値・版付きURL・制覇画面・2回再読込
python tests/audio.py # Web Audioの音程・時刻・分岐・ミュートを計測（実聴ではない）
# 必要に応じて CHROMIUM_PATH=/path/to/chromium TEST_URL=http://localhost:4173 を指定
# インストール済みWebKitがあれば BROWSER=webkit python tests/mobile.py
```

スクリーンショットと機械可読結果は `artifacts/` に生成され、Git管理には含めません。

## CPUの公平性・戦略

`src/game.js` の `prepareRound()` が、**プレイヤー入力を有効にする前**にCPUの札を確定します。受け取るのは双方の公開情報から分かる残り手札と、公開済みの履歴だけです。現在選択中の札は引数になく、確定したCPU札はクロージャに保持します。公開は一度だけ可能です。ゲームはオフラインの一人用で、開発者ツールによる自己改変への対策は目的としていません。

先鋒は練習相手として **5→4→2→1→3** の固定順をルール画面に明記。次鋒は残り札から一様抽選します。中堅・副将・大将は、残りの相手札を一様分布と仮定し、後半の点数も含めた将来の期待得点差を探索します。探索によるsoftmax分布の割合は35%・70%・95%、残りは一様抽選。温度は中堅・副将0.7、大将0.35です。ユーザーの選択癖の学習や、見えていない札の参照はありません。勝率最大化の完全な均衡戦略ではなく、短いカジュアル対戦用です。各相手の傾向はルール画面で確認できます。

`scripts/balance.mjs` の最善応答はCPUの**分布**を知るプレイヤーを評価します。実際に抽選された未公開札は参照せず、最終的な勝ち・負け・引き分けを評価しています。

## 検証・レビュー（2026-10-02）

- `npm test`: 15テスト成功。25通りの対面、全14,400通りの5戦の並び、対称性、得点、引き分け、消費済み札、入力不変性、二重公開拒否を確認。結果の勝敗数と後半得点の集計も検証し、「3勝2敗でも3対4で負ける」ケースを含めています。「1勝1敗3分」の全1,200通りも、1対1・1対2・2対1・2対2の得点が各戦の重みと一致することを確認しています。
- 同じ乱数でプレイヤーの選択を全5通りに変えてもCPU札が不変。CPU乱数は事前確定時の1回のみ。全5相手について全251通りの等サイズの残り手札ペアで合法性・確率の正規化を確認。勝ち抜きの進行、保存値の検証、5ラウンド全勝・全敗・全引き分けの組合せも検証。
- `npm run balance:ladder`: 固定seed `20261002`、5相手×5戦略×各20,000試合、計50万試合。下表はプレイヤー側の勝率です。統計は人間の難易度評価ではありません。

| プレイヤー戦略                       |   先鋒 |   次鋒 |   中堅 |   副将 |   大将 |
| ------------------------------------ | -----: | -----: | -----: | -----: | -----: |
| 無作為                               | 52.23% | 42.03% | 39.36% | 37.16% | 32.13% |
| 小さい札から                         |   100% | 59.33% | 54.41% | 49.33% | 31.95% |
| 大きい札から                         |   100% | 26.74% | 25.89% | 26.20% | 25.79% |
| 2 → 3 → 4 → 1 → 5                    |   100% | 39.50% | 40.07% | 41.25% | 45.41% |
| 公開された残り札への即時期待勝率最大 |   100% | 29.35% | 26.27% | 23.15% | 14.92% |

無作為戦略での引き分け率は先鋒から順に13.95%・16.20%・15.75%・15.98%・14.77%。特定の温存順には強いCPUほど相性がよい場合があり、すべての戦略で難易度が単調に上がるとはしていません。先鋒は説明された固定順から攻略を学ぶ相手です。全測定の勝ち・引き分け・負けと平均得点差はコマンドで再現できます。

昇順固定 **1→2→3→4→5** の追加検証は、乱数試行ではなく全CPU経路を現在の選択確率で重み付けして集計しました（`node scripts/ascending-exact.mjs`）。先鋒は1経路、他は各120経路。浮動小数点の丸めを除き、現行CPUに対する固定戦略の確率です。

| 相手 |   勝ち | 引き分け |   負け |
| ---- | -----: | -------: | -----: |
| 先鋒 |   100% |       0% |     0% |
| 次鋒 | 59.17% |   14.17% | 26.67% |
| 中堅 | 54.15% |   18.88% | 26.97% |
| 副将 | 48.29% |   24.76% | 26.95% |
| 大将 | 32.10% |   43.60% | 24.30% |

先鋒は公開固定順の練習相手なので確実に攻略できます。上位には敗北経路があり必勝ではありませんが、大将でも約75.70%が勝ちか引き分けで、昇順を繰り返して再挑戦する進め方が安定しやすい偏りがあります。CPUは一様な相手を仮定した期待得点差を重視するため、強さを上げても人間の固定順への対応力は上がりません。この更新でCPU方針は変更していません。

音の追加回帰検証は実際のChromium Web Audio APIを計測し、全25対面の勝敗分岐、報告された2対4／4対2、両側の1対5逆転、相打ちの立ち上がり・長さ・ゲイン、通常3結果・特別3結果・制覇2パターンの単一決着音、自動第5ラウンドと決着音の重なり防止、ミュートでの予約音停止、再読込時の制覇音再生なしを確認済みです。音の聴感を自動テストで保証するものではありません。

UIはChromiumのタッチ端末エミュレーションで、320×568、375×548、375×667、390×664、390×844、430×932を検証しました。主要操作・公開履歴の画面内配置、札の変更、ルール画面、音設定保存、勝ち・負け・引き分けまでの通しプレイ、12連打時の入力ロック、全5相手の勝ち抜き・保存後の再開・二周目、最終ラウンド自動公開、全勝・全敗・全引き分け、5種類の勝利演出とCPU側の出し分け、リスタート、reduced-motion、キーボード操作、localStorageが使えない場合を確認。計17シナリオで実行中のJavaScript例外は0件。390×844・390×664ではノッチ47px／ホームインジケーター34pxを模擬し、主要操作が安全領域内に収まることも確認しました。レイアウト確認で見つかった小型画面の履歴・二周目の王冠バッジによるはみ出しと、ルール表示時に説明冒頭が自動スクロールで隠れる問題は修正済みです。320×568でもルールの冒頭と開始ボタンが同時に収まります。

**未確認**: iPhone Safari実機での描画・音の聞こえ方・端末固有のオーディオ復帰・VoiceOver。WebKitのダウンロードは環境の通信制限（403 Domain forbidden）により失敗したため、Safari/WebKit試験済みとはしていません。実機の音量・触感や人間のプレイ感は、エミュレーションの結果とは区別してください。

## リポジトリと公開

- ソース: [monnouchi/duel-five](https://github.com/monnouchi/duel-five)（公開リポジトリ）。
- Pages配信先: <https://monnouchi.github.io/duel-five/>。有効化・配信済みです。
- [Test and deploy Pages](https://github.com/monnouchi/duel-five/actions/workflows/pages.yml) が `main` のpushと手動実行でテスト・ビルド・公開を行います。PRではテストとビルドだけを実行します。
- 推奨設定は **Settings → Pages → Build and deployment → Source: GitHub Actions**。現在はブランチ式の `pages-build-deployment` も動作しているため、二重実行を解消する場合はここでActionsに統一します。
- Node.js 24で `npm test` → `npm run build` を実行し、**`dist/` の中身だけ**をPages artifactとして配信します。リポジトリルート、テスト、検証画像、開発ツールはサイトに含めません。
- JavaScript/CSS参照は相対パスなので `/duel-five/` 配下でも動作します。Node常駐、APIキー、新規サービス契約は不要です。
- ワークフローの権限はビルドの `contents: read` と配信の `pages: write` / `id-token: write` に限定。PATなどの長期認証情報は追加しません。

GitHub Pagesは有効化済みです。mainへの更新はテスト・ビルドに成功すると自動配信されます。

更新時にHTMLと古いJS/CSSが混ざることを防ぐため、HTMLのCSS・JS参照とJSのゲームモジュール参照には版付きURLを使います。現在の版は `2026.10.03-1`。ルール画面下部の「読込版」でHTML・JS・CSSの一致を確認できます。配信ファイルを変更するときは `index.html` の `data-release` とURL、`src/app.js` の `RELEASE` とimport URL、`src/style.css` の `--release` を同じ新しい版へ更新してください。

制覇画面追加前のJSと新HTMLの混在では、通常結果画面のままになることを再現しました。新しいファイルが揃った状態では旧版の完了データをそのまま読み込み、再読込を2回行っても成績・制覇回数は変わりません。新たな大将勝利では王冠の登場演出と専用音を一度だけ実行し、再読込時は静かな終幕表示になります。演出済みフラグで達成記録を消す処理はありません。動きを減らす設定や音OFFでも終幕画面自体は表示します。

## 構成

- `index.html`: 日本語の対戦画面・ルールダイアログ
- `src/game.js`: 純粋な勝敗処理・CPU探索・事前確定
- `src/app.js`: 入力状態、カード演出、粒子、Web Audio
- `src/style.css`: レスポンシブ配置、カード装飾、reduced-motion
- `scripts/`: 依存不要のビルド・プレビュー、バランス測定
- `tests/`: ルール/公平性単体テストとモバイル操作回帰テスト
